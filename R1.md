
**KISEKKA ONLINE — Phase 1: Project Setup & Authentication**

You are building a React Native mobile app called **Kisekka Online** using **Expo** and **Firebase**. This is a community marketplace app for Kisekka Market in Kampala, Uganda.

**Stack:**
- Expo (latest SDK, bare or managed workflow)
- Firebase (Firestore, Firebase Auth, Firebase Storage config only — actual media goes to Cloudflare R2)
- React Navigation for routing
- Clean, modern UI — think Instagram/Facebook familiarity

---

**Task: Set up the project and implement authentication**

**1. Project Setup**
- Initialise a new Expo project called `kisekka-online`
- Set up folder structure as follows:
```
/app
/components
/screens
  /auth
  /onboarding
/hooks
/services
  firebase.tsx
  auth.tsx
/store
/constants
  theme.tsx
/assets
```
- Set up React Navigation with two root stacks: `AuthStack` and `AppStack`
- Create `theme.tsx` with a clean modern design system — primary color `#1A73E8`, neutral grays, consistent spacing and typography scale

**2. Firebase Setup**
- Initialise Firebase project config in `services/firebase.tsx`
- Enable Firebase Auth with Phone Number as primary provider
- Enable Google Sign-In as secondary provider
- Use environment variables via `app.config.tsx` for all Firebase credentials — never hardcode keys

**3. Authentication Screens**

Build these screens in `/screens/auth/`:

`WelcomeScreen` — App logo, tagline, "Continue with Phone" button (primary), "Continue with Google" button (secondary), clean and minimal

`PhoneEntryScreen` — Phone number input with Uganda (+256) as default country code but allow changing, "Send OTP" button, basic validation

`OTPVerificationScreen` — 6-digit OTP input, countdown timer for resend, "Verify" button, handle wrong OTP error gracefully

`GoogleAuthHandler` — Not a visible screen, just handles the Google Sign-In flow and redirects appropriately

**4. Onboarding Screen**

After first-time auth (new user only), route to `/screens/onboarding/ProfileSetupScreen`:
- Shop name (required)
- Display name (required)
- WhatsApp number (required) — pre-fill with phone number if phone auth was used
- Market location / stall description (required)
- Categories multi-select (required, minimum 1) — use these fixed options to start:
  `Japanese Cars, European Cars, American Cars, Trucks & Commercial, Motorcycles, Electronics & Electrical, Tyres & Rims, Body Parts, Engine & Transmission, Tools & Equipment, General Hardware, Other`
- Profile photo (optional, skip allowed)
- On submit, create a document in Firestore `users/{userId}` with these fields:
```
displayName, shopName, marketLocation, whatsappNumber,
profilePhotoUrl (null if skipped), categories[],
followersCount: 0, followingCount: 0,
createdAt: serverTimestamp(), isVerified: false
```

**5. Auth State Management**
- Use a custom `useAuth` hook in `/hooks/useAuth.tsx`
- On app load, check auth state — if user exists in Firebase Auth AND has a Firestore user document, go to `AppStack`. If authed but no Firestore document (new user), go to onboarding. If not authed, go to `AuthStack`
- Persist auth state across app restarts

**6. AppStack Placeholder**
- Create a simple placeholder `HomeScreen` that shows "Welcome to Kisekka Online, {displayName}" just to confirm the full flow works end to end

---

**Firestore Security Rules for this phase:**
```
users/{userId} — read: any authenticated user, write: owner only
```

---

**Deliverables:**
- Full working auth flow: Welcome → Phone/Google → Onboarding (new users) → Home
- Returning users skip onboarding and go straight to Home
- All screens mobile-friendly, consistent with theme.tsx
- No hardcoded credentials
- Code should be clean, commented, and production-minded from the start
