**2. Feed Score Algorithm**

When fetching posts, fetch the latest 100 active posts from Firestore then rank them client-side using this scoring formula:

```ts
const hoursSincePosted = (now - post.createdAt) / 3600000
const recencyScore = Math.max(0, 1 - hoursSincePosted / 72) // decays over 72 hrs

const categoryMatchScore = post.categories.some(c =>
  currentUser.categories.includes(c)) ? 1 : 0

const isFollowing = followingIds.includes(post.authorId)
const followBoost = isFollowing ? 1 : 0

const engagementScore = Math.min(1,
  (post.whatsappTapCount * 3 + post.saveCount * 2 + post.viewCount * 0.1) / 100
)

const score = (recencyScore * 1)
            + (categoryMatchScore * 2)
            + (followBoost * 3)
            + (engagementScore * 1.5)
```

Sort posts by score descending before rendering. Implement this in a reusable hook `hooks/useFeed.ts`.

```

               — create: authenticated user, authorId must equal request.auth.uid
               — update: owner only (for whatsappTapCount and saveCount, allow any authenticated user)

saved/{userId}/posts/{postId} — read/write: owner only
```

**Critical implementation notes:**
- `whatsappTapCount` is the single most important metric in this app — make absolutely sure every tap is tracked reliably even if the Firestore write fails silently, log it
- Never block the WhatsApp deep link waiting for the Firestore write — fire the increment then immediately open WhatsApp
- All media URLs stored in Firestore must be the R2 public URLs, never local paths
- Feed must work with zero posts (empty state) and with no internet (show last cached data via Firestore offline persistence)
- Keep the scoring algorithm in one place (`hooks/useFeed.ts`) so it is easy to tune later
